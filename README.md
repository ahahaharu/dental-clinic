# 🦷 Dental Clinic Management System

Информационная система для автоматизации работы стоматологической клиники. Приложение позволяет управлять расписанием врачей, вести учет пациентов, управлять прайс-листом и складскими запасами, а также отслеживать финансовую статистику.

---

## 🚀 Основные возможности

* **Журнал записи:** Интерактивный календарь приемов со статусами.
* **Учет пациентов:** Личные дела и медицинские карты (диагнозы, аллергии).
* **Управление услугами:** Прайс-лист с технологическими картами (привязка материалов и оборудования к процедуре).
* **Финансы:** Автоматический расчет стоимости приема на основе оказанных услуг.
* **Складской учет:** Учет расходных материалов и оборудования, контроль остатков.
* **Аналитика:** Дашборд с ключевыми показателями эффективности клиники.

---

## 📚 Руководство пользователя

### 1. 📊 Дашборд (Обзор клиники)
Стартовая страница приложения, отображающая текущее состояние дел.
* **Пациентов:** Общее количество зарегистрированных клиентов.
* **Приемов сегодня:** Количество записей на текущую дату.
* **Выручка (мес):** Сумма всех завершенных приемов за текущий месяц.
* **Топ услуга:** Самая популярная процедура по частоте выполнения.
* **Склад:** Индикатор критического остатка материалов (если позиций < 10, рамка становится оранжевой).

### 2. 📅 Журнал записи (Appointments)
Основной инструмент администратора.
* **Просмотр:** Календарь с цветовой индикацией статусов:
    * 🔵 *Синий:* Запланирован.
    * 🟢 *Зеленый:* Завершен (услуги оказаны, счет выставлен).
    * 🔴 *Красный:* Отменен.
* **Создание записи:** Нажмите кнопку **"Записать пациента"**. Выберите пациента, врача, дату/время и кабинет.
* **Проведение приема:**
    1.  Нажмите на запись в календаре.
    2.  Нажмите **"Завершить прием"**.
    3.  В открывшемся окне выберите из списка **оказанные услуги** (можно выбрать несколько).
    4.  Система автоматически сохранит услуги, спишет материалы (логика на будущее) и рассчитает итоговый счет.
* **Просмотр счета:** В завершенном приеме отображается детализация: список процедур и итоговая сумма.

### 3. 👥 Пациенты (Patients)
База данных клиентов.
* **Поиск:** По фамилии, имени или телефону.
* **Карточка пациента:**
    * Личные данные (ФИО, телефон, дата рождения).
    * **Кнопка "Карта":** Открывает медицинскую карту, где врач может указать хронические диагнозы и аллергии (важно для анестезии).

### 4. 💉 Прайс-лист и Услуги (Treatments)
Каталог процедур, которые оказывает клиника.
* **Добавление услуги:** При создании можно указать название, цену и длительность.
* **Технологическая карта (Важно!):**
    * В форме услуги есть блок **"Технологическая карта"**.
    * Вы можете привязать к услуге **Материалы** (например, "Пломба" требует "Композит - 1 шт") и **Оборудование**.
    * Это позволяет видеть структуру себестоимости услуги.
* **Просмотр:** Нажав на иконку 👁️ (глаз), можно увидеть состав услуги (какие материалы входят) без режима редактирования.

### 5. 📦 Склад (Inventory)
Учет материально-технической базы. Разделен на две вкладки:
* **Материалы:** Расходники (перчатки, анестезия, пломбировочный материал). Отслеживается количество и срок годности.
    * *Индикация:* Если количество меньше 10, число подсвечивается красным.
* **Оборудование:** Учет техники (кресла, рентгены). Отслеживается серийный номер, статус (работает/в ремонте) и привязка к кабинету.

### 6. 👨‍⚕️ Сотрудники (Staff)
Управление персоналом.
* **Стоматологи:** Данные о врачах, специализация, лицензии и график работы.
* **Ассистенты:** Данные о среднем медицинском персонале.

## 🛠 Технический стек

* **Frontend:** React.js, React Router, Ant Design (UI Kit).
* **Backend:** Node.js, Express.js.
* **Database:** MySQL (основные данные), Redis (сессии, кэш, Pub/Sub), MongoDB (журнал действий).

## ⚙️ Запуск проекта

### Предварительные требования
* Node.js 20+
* Docker Desktop (MySQL, Redis и MongoDB запускаются в контейнерах — ставить их локально не нужно)

### Установка и запуск

1.  **Запустите базы данных:**
    ```bash
    docker compose up -d
    ```
    При первом запуске MySQL автоматически импортирует `dental_clinic.sql` (схема + тестовые данные + пользователь `admin` / `admin123`).

2.  **Настройте окружение:**
    ```bash
    cp api/.env.example api/.env
    ```
    Значения по умолчанию совпадают с `docker-compose.yml`. Задайте свой `JWT_SECRET`.

3.  **Установите зависимости:**
    ```bash
    npm install
    ```

4.  **Запустите бэкенд** (в отдельном терминале):
    ```bash
    npm run server
    # API: http://localhost:5001
    ```

5.  **Запустите фронтенд:**
    ```bash
    npm run dev
    # Приложение: http://localhost:5173
    ```

### Полезные команды
* `npm run add-user` — добавить пользователя (admin / dentist / assistant).
* `docker compose down` — остановить базы (данные сохраняются).
* `docker compose down -v` — остановить и удалить данные; при следующем `up` БД пересоздастся из `dental_clinic.sql`.

> Порт 5000 на macOS занят AirPlay Receiver, поэтому API работает на 5001. Адрес API для фронтенда можно переопределить переменной `VITE_API_URL`.

## 🔄 Типовой сценарий работы (Workflow)

1.  Администратор добавляет нового **Пациента** в базу.
2.  Администратор переходит в **Журнал записи**, выбирает свободное время у врача и создает запись.
3.  Пациент приходит на прием. Врач выполняет работу.
4.  Врач/Администратор открывает запись в календаре, нажимает **"Завершить прием"**.
5.  В списке услуг выбираются выполненные процедуры (например, "Лечение кариеса" и "Анестезия").
6.  Приложение автоматически формирует счет на оплату.
7.  Данные о выручке и количестве пациентов обновляются на **Дашборде** в реальном времени.
